## Что уже реализовано
- **Шаг 2.7 (новое):** изменил структуру генерации Mining World — теперь это
  «чистый» пещерный мир в стиле ванильных пещер, **без воды, без лавы, без
  травы/гравия-пятен и без структур**.
  Причина: на шаге 2.6 вывод «воды нет» оказался **неверным** — при
  отключённых аквиферах ванильный механизм `FluidPicker` жёстко заливает все
  открытые полости **ниже уровня моря** дефолтной жидкостью (`sea_level=32`,
  `default_fluid=water` → вода в нижней трети пещер), а `surface_rule`-заглушки
  пресета `minecraft:caves` клали grass/dirt/gravel-полосы.
  Что сделано:
  - новый `worldgen/noise_settings/caves.json` (`moggminingworld:caves`) —
    копия ванильного `overworld.json` (реально ванильное карвинг-пещер:
    cheese/spaghetti/noodle, глубина вплоть до коренных пород), но с
    `sea_level: 0`, `aquifers_enabled: false`, `ore_veins_enabled: false`;
  - `surface_rule` заменён на простой: deepslate в 0..16, stone выше —
    **ни травы, ни гравия, ни песка** больше нет;
  - `dimension/mining_world.json` — `settings` теперь `moggminingworld:caves`;
  - `dimension_type/mining_world.json` — `min_y: 0`, `height: 320`,
    `logical_height: 320`. Ключевое: мир начинается с Y=0, а `sea_level: 0`,
    поэтому **воде физически негде появиться** (всё ниже 0 за пределами мира),
    лава тоже отсутствует;
  - `top_bedrock` height 383 → **319** (при новом `min_y=0` это Y=319 —
    потолок), `bottom_bedrock` height 0 (=Y=0 — пол). Колонна 0..320.
  не менялось: биом, `MiningWorldEffects`/рендер (2.5), команды входа.
  Сборка/тест не выполнялись в этом ответе (нет доступа к сети/Minecraft
  в этой среде) — см. «Как проверить» ниже.
- **Шаг 3.0 (новое):** ванильные руды в Mining World.
  Мир начинается с Y=0 (dimension_type `min_y: 0`, `height: 320`), глубинный
  сланец в 0..16, камень выше (surface_rule из шага 2.7). Поэтому все руды
  определены **своими** configured/placed-фичами (а не ссылкой на ванильные
  `minecraft:ore_*`, чтобы не зависеть от имён реестра и не пытаться
  генерировать руды на недостижимых Y<0) и привязаны к блокам `stone`/`deepslate`
  через `block_match`, с диапазонами Y, обрезанными под нашу колонну 0..320:
  - `coal` — Y 0..320, count 24, size 17 (частый, по всей колонне);
  - `copper` — Y 0..112, count 16, size 10;
  - `iron` — Y 0..80, count 12, size 9;
  - `gold` — Y 80..320, count 6, size 9;
  - `redstone` — Y 0..32, count 8, size 8;
  - `lapis` — Y 0..64, count 4, size 7;
  - `diamond` — Y 0..16, count 3, size 4 (только в глубинном сланце);
  - `emerald` — Y 0..320, count 2, size 5 (редкий рассеянный).
  Каждый — пара файлов `worldgen/configured_feature/ore_*.json`
  (`minecraft:ore`, `discard_chance_on_air_exposure: 0`, два таргета:
  `stone`→`*_ore`, `deepslate`→`deepslate_*_ore`) и
  `worldgen/placed_feature/ore_*.json` (`count` + `in_square` +
  `height_range`(uniform) + `biome`).
  Подключены в биоме `mining_world.json` в 7-й список `features`
  (`GenerationStep.Decoration.UNDERGROUND_ORES`, индекс 6) —
  `top_bedrock`/`bottom_bedrock` остались в индексе 0 (`RAW_GENERATION`).
  Это **не** модовые руды (их Этап 4) и не ore_veins (отключены в noise
  settings, шаг 2.7). Сборка/тест не выполнялись в этом окружении (нет
  сети/Minecraft) — проверка в игре ниже.
  **Исправления после крашей (реальный клиент 1.20.1, Forge 47.4.10):**
  - `placed_feature/ore_*.json`: ключ у `minecraft:uniform` HeightProvider —
    **`max_inclusive`**, а не `max_exclusive` (иначе
    `No key max_inclusive` и краш загрузки реестров).
  - `configured_feature/ore_*.json`: у поля `target` (RuleTest) в
    `minecraft:ore` ключ — **`predicate_type`**, а не `type`
    (иначе `Input does not contain a key [predicate_type]`). Верхний
    `"type": "minecraft:ore"` трогать нельзя.
  Обе ошибки были в моих JSON и исправлены; после правок все 16 файлов
  проходят JSON-парс и реестр грузится.
- **Шаг 2.6 (верификация, код не менялся):** вода в Mining World не
  генерируется — делать нечего. Исходная гипотеза шага («vanilla
  `minecraft:caves` заливает большие пещеры водой») **не подтвердилась**.
  Проверено по фактическому ванильному файлу
  `data/minecraft/worldgen/noise_settings/caves.json` (извлечён из
  vanilla client-1.20.1.jar):
  - `aquifers_enabled: false` — симуляция аквиферов отключена;
  - `noise_router.fluid_level_floodedness: 0`, `fluid_level_spread: 0`,
    `lava: 0` — уровень жидкости нигде не превышает порог, и
    `default_fluid: water` в генерации не размещается;
  - все блоки `minecraft:water` в `surface_rule` стоят только под
    условиями `biome_is` ванильных болот/океанов/льдов (никогда не
    совпадают с `moggminingworld:mining_world`) либо являются
    материальными условиями `minecraft:water` («блок под водой?») —
    они воду не ставят;
  - у нашего биома (шаг 2.2) пустые `features` — вода через spring-фичи
    тоже не появляется.
  Дополнительно исправлены неточности прошлых шагов по факту того же
  файла: `sea_level` = **32** (а НЕ -32, как писал шаг 2.1), а
  `noise.height` = **192**, т.е. рельеф пресета охватывает **-64..128**
  (а НЕ -64..320). Выше Y=128 до потолка из шага 2.3 — пустота. Не
  трогалось: потолок (2.3) и пол (2.4) заданы `fill_layer`-фичами и
  работают независимо от высоты пресета (см. «Известные проблемы»).
- **Шаг 2.5 (новое):** клиентский `DimensionSpecialEffects` для Mining World.
  Это чисто рендер-класс — генерация мира не тронута.
  Новые файлы:
  - `client/MiningWorldEffects.java` — наследник `DimensionSpecialEffects`,
    форма скопирована с ванильных `NetherEffects`/`EndEffects` (единственные
    два ванильных измерения "без настоящего неба"): `cloudLevel = NaN`

    `constantAmbientLight = false`. В отличие от Nether, `isFoggyAt()`
    возвращает `false` — не форсируем доп. туман поверх того, что уже
    даёт `fog_color` биома (сделано на шаге 2.2).
  - `client/ClientModEvents.java` — `@Mod.EventBusSubscriber` с
    `bus = MOD`, `value = Dist.CLIENT`, слушает
    `RegisterDimensionSpecialEffectsEvent` и регистрирует
    `MiningWorldEffects` под ключом `moggminingworld:mining_world`.
    Класс и подписанный метод из-за `value = Dist.CLIENT` не грузятся и
    не вызываются на выделенном сервере.
  - `dimension_type/mining_world.json` — поле `effects` переключено с
    `minecraft:the_end` (временная заглушка с Этапа 1) на
    `moggminingworld:mining_world`. Это обязательное условие: если
    строка тут не совпадает с ключом регистрации — клиент молча
    откатится на рендер оверворлда с предупреждением в логе.
  Сборка/тест не выполнялись в этом ответе (нет доступа к сети/Minecraft
  в этой среде).
- **Шаг 2.4:** bedrock-пол мира.
  Решение принято по аналогии с 2.3, а не по результату теста (в этой
  среде нет возможности реально запустить Minecraft-сервер и проверить
  поведение пресета `minecraft:caves` внизу колонны) — сделано явным и
  безопасным способом: добавлен свой `fill_layer` слой по нижней границе,
  зеркально верхнему из 2.3. Даже если у пресета `minecraft:caves` уже
  был бы "бесплатный" ванильный bedrock-пол снизу — повторная заливка
  bedrock тем же блоком безвредна (идемпотентно), а если его не было —
  теперь пол гарантированно есть. **Это всё ещё нужно подтвердить
  реальным тестом в игре** (см. "Как проверить" ниже) — в частности,
  что нет двойного/рваного слоя или конфликта с руд-генерацией на
  будущих этапах (Y=-64 — самый нижний, ниже руд копать не должно
  получаться в принципе).
  Новые файлы:
  - `worldgen/configured_feature/bottom_bedrock.json` — `fill_layer` с
    `height: 0` (это Y=-64 при `min_y = -64`, самый нижний блок полной
    колонны -64..320) и состоянием `minecraft:bedrock`.
  - `worldgen/placed_feature/bottom_bedrock.json` — обёртка без модификаторов
    размещения, как и `top_bedrock` из 2.3.
  - `worldgen/biome/mining_world.json` — `moggminingworld:bottom_bedrock`
    добавлен вторым элементом в `features[0]` (`RAW_GENERATION`, тот же шаг,
    что и `top_bedrock`).
  Сборка/тест не выполнялись в этом ответе (нет доступа к сети/Minecraft
  в этой среде) — см. пункт 6 общих правил.

  - `worldgen/placed_feature/top_bedrock.json` — обёртка без модификаторов

  - `worldgen/biome/mining_world.json` — `moggminingworld:top_bedrock`

## Как проверить (шаг 2.7)
1. Дождаться сборки, положить новый `.jar` в `mods`.
2. **Обязательно** удалить мининг-мир в мире: `world/dimensions/moggminingworld`
   (старые чанки с водой/травой из генерации до 2.7 не обновятся сами).
3. `/execute in moggminingworld:mining_world run tp @s 0 60 0` и облететь
   несколько пещер. Ожидаемый результат: **только камень и воздух** (дипслейт
   внизу), **ноль воды и лавы**, ноль травы/гравия, ноль структур.
4. Копать вверх/вниз: на Y=319 сплошной bedrock-потолок, на Y=0 bedrock-пол.
   Пещеры — ванильного стиля (cheese/spaghetti/noodle), как в оверворлде.
5. Сообщить: есть ли где-нибудь вода/лава/трава/структуры; нравится ли
   рельеф (ванильные пещеры на всю колонну 0..320).

## Как проверить (шаг 3.0)
1. Дождаться зелёной сборки, скачать `.jar`.
2. **Обязательно** удалить старый мининг-мир в мире: `world/dimensions/moggminingworld`
   (старые чанки без руд не обновятся сами).
3. `/execute in moggminingworld:mining_world run tp @s 0 60 0` и покопать
   пещеры в разных диапазонах Y. Ожидаемый результат: в камне/глубинном
   сланце появляются ванильные руды — `coal`, `copper`, `iron` (низ),
   `gold` (высоко, Y>80), `redstone` (Y 0..32), `lapis` (Y 0..64),
   `diamond` (только Y 0..16, в deepslate), `emerald` (редко везде).
4. Проверить, что deepslate-варианты руд ставятся в 0..16, а обычные —
   выше (это даёт `block_match` по `deepslate`/`stone` в configured-фиче).
5. Убедиться, что НЕТ воды/лавы (это шаг 2.7) и что руды НЕ генерятся
   в воздухе пещер (орудуют только по камню — `discard_chance_on_air_exposure: 0`,
   так что блоб может ужиматься у границы воздуха, это нормально).
6. Сообщить: какие руды нашлись/не нашлись, не слишком ли густо/редко,
   совпадает ли глубина (алмазы реально только внизу). По результату
   подправим count/size/диапазоны в placed_feature перед Этапом 4.

## Как проверить (шаг 2.6)
1. Пересборка не нужна — код не менялся, берём последний собранный `.jar`
   (или собираем заново, если хочется).
2. Если тестируешь на мире, где чанки Mining World генерировались **до
   шага 2.2** (когда биом был `minecraft:dripstone_caves` со spring-фичами) —
   удали `world/dimensions/moggminingworld/mining_world`, чтобы старые
   чанки с водой не остались.
3. `/execute in moggminingworld:mining_world run tp @s 0 60 0` и облететь
   несколько пещер. Ожидаемый результат: **воды нет** — только камень,
   воздух и лавовые... нет, лавы тоже нет (`lava: 0`). Ни озёр, ни
   водопадов, ни луж.

## Как проверить (шаг 2.1)
1. Дождаться зелёной сборки в GitHub Actions, скачать `.jar` из Artifacts.
2. Положить `.jar` в папку `mods` тестового Forge 1.20.1 сервера (с читами/OP).
   **Важно:** если тестируешь на уже существующем мире, где Mining World
   раньше сгенерировался как плоский (Этап 1) — удали папку
   `world/dimensions/moggminingworld/mining_world` перед стартом, иначе
   старые плоские чанки останутся на месте и новая генерация будет видна
   только на новых, ранее не посещённых координатах.
3. Запустить сервер, проверить лог на строку про "Mining World dimension is
   registered and loaded" (как и раньше).
4. Зайти оператором, выполнить:
   ```
   /execute in moggminingworld:mining_world run tp @s 0 60 0
   ```
   (координата Y = 60, а не -60 — теперь это середина полной колонны высот,
   в отличие от плоской заглушки Этапа 1).
5. Ожидаемый результат: игрок оказывается либо в камне (тогда нужно

   чтобы попасть в воздух над пещерами), либо сразу видит пещерный рельеф —
   неровные своды, гроты, обычный камень/глубинный сланец. Копая вверх —
   упираешься в bedrock. Копая вниз — тоже bedrock. Неба и облаков нет.
6. **На что специально посмотреть и сообщить в следующем сообщении:**
   - есть ли большие полости, залитые водой (обновлено шагом 2.6: воды
     быть не должно — пресет `minecraft:caves` не заливает пещеры, см.
     раздел «Как проверить (шаг 2.6)»);
   - нет ли крашей чанк-генератора в логе.
7. Вернуться: `/execute in minecraft:overworld run tp @s 0 100 0`.

## Известные проблемы / ограничения
- Шаг 2.5 (клиентский рендер неба/облаков) не проверен вживую — только
  написан по образцу ванильных `NetherEffects`/`EndEffects`. Нужен
  реальный заход клиентом в измерение для подтверждения.
- Bedrock-потолок сейчас идеально плоский (один сплошной слой на Y=319),
  без ванильной "рваной" текстуры, как в потолке Nether (там неровный
  край через `count`/шум в плейсменте). Это осознанное упрощение ради
  малого риска в этом шаге — ровный потолок так же не даёт выйти за
  пределы мира. Если понадобится "рваный" вид — отдельный полировочный шаг.
- Свой биом подключён, но он **полностью пустой** (нет ни руд, ни спелеотем,
  ни мобов) — это ожидаемо, наполнение идёт по этапам 3+.
- Вода и лава **с шага 2.7 не генерируются вовсе** (это свойство
  `moggminingworld:caves`: `sea_level: 0` при `min_y: 0` — заливать
  нечего). Шаг 2.6, который «доказывал» отсутствие воды в пресете
  `minecraft:caves`, был ошибочен: при `aquifers_enabled: false`
  ванильный `FluidPicker` заливает все открытые полости ниже `sea_level`
  (`default_fluid: water`) — вода в нижней части пещер была. Если в мире
  всё же встретится вода/трава — это старые чанки с генерации до 2.7,
  их нужно удалить (см. «Как проверить» шага 2.7).
- Пустота между Y=128 и Y=318: рельеф пресета `minecraft:caves`
  заканчивается на Y=128 (`noise.height` = 192, `min_y` = -64), выше —
  воздух до потолка из шага 2.3 (Y=319). Плюс у самого пресета есть
  ванильный "рваный" bedrock-потолок около Y=123..128 — итого сверху
  два потолка и большая пустая полость. Осознанное состояние: потолок
  2.3 нужен как верхняя граница, а заполнение/утилизация пустоты —
  отдельный вопрос будущих этапов.
- Нет способа попасть в измерение через игровой интерфейс (только команда) —
  это ожидаемо, портал будет на Этапе 5.
- gradlew/gradle-wrapper.jar по-прежнему не добавлены (см. ограничение Этапа 0);
  сборка всё ещё идёт через `gradle/actions/setup-gradle` в GitHub Actions.
