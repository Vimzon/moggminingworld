## Что уже реализовано
- **Шаг 2.3 (новое):** bedrock-потолок мира.
  **Отклонение от исходного плана:** вместо правки `surface_rule` внутри
  noise settings (это означало бы либо копировать весь ванильный
  `minecraft:caves` пресет целиком — риск ошибки, как и предупреждали
  на шаге 2.1, — либо пытаться "подменить" часть чужого registry-объекта,
  что в датапаках невозможно), использован тот же механизм, которым сам
  ванильный Nether делает bedrock-потолок и bedrock-пол: **`minecraft:fill_layer`**
  configured feature, вызываемая как placed feature на шаге `RAW_GENERATION`.
  Новые файлы:
  - `worldgen/configured_feature/top_bedrock.json` — `fill_layer` с
    `height: 383` (это Y=319 при `min_y = -64`, самый верхний блок полной
    колонны -64..320) и состоянием `minecraft:bedrock`.
  - `worldgen/placed_feature/top_bedrock.json` — обёртка без модификаторов
    размещения (как ванильные `bedrock_floor`/`bedrock_ceiling`), заливает
    сразу весь чанк по этому Y.
  - `worldgen/biome/mining_world.json` — `moggminingworld:top_bedrock`
    добавлен в `features[0]` (`RAW_GENERATION`, первый шаг декорации —
    до руд/структур/т.д., что соответствует тому, как размещаются
    ванильные bedrock-слои).
  Нижняя граница (2.4) специально НЕ трогалась в этом шаге — по плану
  это отдельный шаг, хотя нижний bedrock, вероятно, уже есть "бесплатно"
  из самого пресета `minecraft:caves` (у него `min_y = -64` с обычным
  ванильным bedrock-полом оверворлда). Это будет явно проверено в 2.4,
  а не предполагается заранее.
- **Шаг 2.2:** `data/moggminingworld/worldgen/biome/mining_world.json` —
  свой минимальный биом Mining World:
  - `has_precipitation: false` (без дождя/снега — измерение подземное);
  - все категории `spawners` пустые (`monster`, `creature`, `ambient`,
    `axolotls`, `underground_water_creature`, `water_ambient`,
    `water_creature`, `misc`) — по умолчанию **ничего не спавнится**,
    мобов для Mining World будем добавлять осознанно на будущих этапах,
    а не наследовать ванильный список dripstone_caves;
  - `carvers: []` — без ванильных пещерных carver'ов (у нас и так весь
    рельеф от noise settings пресета `minecraft:caves`, доп. carvers не нужны);
  - `features` — 11 пустых списков (по одному на каждый шаг
    `GenerationStep.Decoration`) — без руд, воды, растений, спелеотем и т.д.
    Руды появятся на Этапе 3, вода/аквиферы разбираются отдельно на шаге 2.6
    (это на уровне density function, не через features биома);
  - `fog_color`/`sky_color`/`water_color`/`water_fog_color` — тёмные
    нейтральные значения, без привязки к эстетике dripstone_caves.
  `data/moggminingworld/dimension/mining_world.json` — `biome_source.biome`
  переключён с `minecraft:dripstone_caves` на `moggminingworld:mining_world`.
  Noise settings (`minecraft:caves`) не трогались — это отдельно от биома.
- **Шаг 2.1:** `data/moggminingworld/dimension/mining_world.json` больше
  не плоская заглушка. Генератор теперь `minecraft:noise` со ссылкой на
  **ванильный пресет** `minecraft:caves` (`settings: "minecraft:caves"`) —
  это те же noise settings, на которых основан подземный мир в самом
  Minecraft 1.20.1: полная колонна -64..320, bedrock-потолок и bedrock-пол,
  пещерный рельеф без обычной поверхности, уровень моря по умолчанию -32.
  **Отклонение от исходного плана:** вместо ручного копирования всего
  density-function JSON (это тысячи строк и очень легко сломать) я просто

  (используется буквально тот же файл), а риск ошибки — намного ниже.
  Если позже понадобится реально кастомизировать density functions —
  сделаем это отдельным шагом уже на готовой рабочей базе.
  Биом пока **временный placeholder**: `minecraft:dripstone_caves` через
  `minecraft:fixed` biome source — просто чтобы генератор был валиден.
  Свой биом Mining World (без обычных пещерных мобов/декораций по умолчанию)
  будет в шаге 2.2.
- Всё из Этапа 0 (см. git-историю, файлы не переписывались без необходимости).

## Как проверить (шаг 2.3)
1. Дождаться зелёной сборки, скачать `.jar`.
2. Если тестируешь на мире, где Mining World уже генерировался раньше —
   удали `world/dimensions/moggminingworld/mining_world` (bedrock-потолок
   применяется через feature при генерации чанка, на уже сгенерированных
   чанках его не будет).
3. `/execute in moggminingworld:mining_world run tp @s 0 300 0`.
4. Лететь/копать вверх (креатив + полёт удобнее). Ожидаемый результат:
   на Y=319 сплошной слой bedrock, дальше не пройти обычным способом.
5. Проверить несколько разных X/Z (не только точку 0 0), чтобы убедиться,
   что слой сплошной по всему чанку/миру, а не только в одной точке.
6. Сообщить: действительно ли на Y=319 сплошной bedrock везде, нет ли
   дыр/крашей в логе при генерации чанков.

## Как проверить (шаг 2.2)
1. Дождаться зелёной сборки, скачать `.jar`.
2. Если тестируешь на мире, где Mining World уже генерировался (шаг 2.1
   или раньше) — удали `world/dimensions/moggminingworld/mining_world`,
   иначе старые чанки со старым биомом останутся как есть.
3. Зайти оператором, `/execute in moggminingworld:mining_world run tp @s 0 100 0`.
4. Проверить: `/execute in moggminingworld:mining_world run data get entity @s`
   не обязателен; проще — `F3` (debug screen) должен показывать биом
   `moggminingworld:mining_world`, а не `minecraft:dripstone_caves`.
5. Убедиться, что мобы **не спавнятся** сами по себе (подождать немного
   в освещённой/тёмной пещере) — это ожидаемо на этом шаге.
6. Рельеф пещер должен остаться таким же, как в 2.1 (биом не влияет на
   форму пещер, только на декорации/мобов/цвета) — если рельеф вдруг
   изменился, это баг.
7. Сообщить в следующем сообщении: показывает ли F3 правильный биом,
   нет ли крашей в логе при заходе в чанки Mining World.

## Как проверить (шаг 2.1)
1. Дождаться зелёной сборки в GitHub Actions, скачать `.jar` из Artifacts.
2. Положить `.jar` в папку `mods` тестового Forge 1.20.1 сервера (с читами/OP).
   **Важно:** если тестируешь на уже существующем мире, где Mining World
   раньше сгенерировался как плоский (Этап 1) — удали папку
   `world/dimensions/moggminingworld/mining_world` перед стартом, иначе
   старые плоские чанки останутся на месте и новая генерация будет видна
   только на новых, ранее не посещённых координатах.
3. Запустить сервер, проверить лог на строку про "Mining World dimension is
   registered and loaded" (как и раньше).
4. Зайти оператором, выполнить:
   ```
   /execute in moggminingworld:mining_world run tp @s 0 60 0
   ```
   (координата Y = 60, а не -60 — теперь это середина полной колонны высот,
   в отличие от плоской заглушки Этапа 1).
5. Ожидаемый результат: игрок оказывается либо в камне (тогда нужно
   `/execute in moggminingworld:mining_world run tp @s 0 100 0` или ещё выше,
   чтобы попасть в воздух над пещерами), либо сразу видит пещерный рельеф —
   неровные своды, гроты, обычный камень/глубинный сланец. Копая вверх —
   упираешься в bedrock. Копая вниз — тоже bedrock. Неба и облаков нет.
6. **На что специально посмотреть и сообщить в следующем сообщении:**
   - есть ли большие полости, залитые водой (это нормально ожидать на этом
     шаге — воду ещё не трогали, это будет отдельный шаг 2.6);
   - нет ли крашей чанк-генератора в логе.
7. Вернуться: `/execute in minecraft:overworld run tp @s 0 100 0`.

## Известные проблемы / ограничения
- Bedrock-потолок сейчас идеально плоский (один сплошной слой на Y=319),
  без ванильной "рваной" текстуры, как в потолке Nether (там неровный
  край через `count`/шум в плейсменте). Это осознанное упрощение ради
  малого риска в этом шаге — ровный потолок так же не даёт выйти за
  пределы мира. Если понадобится "рваный" вид — отдельный полировочный шаг.
- Свой биом подключён, но он **полностью пустой** (нет ни руд, ни спелеотем,
  ни мобов) — это ожидаемо, наполнение идёт по этапам 3+.
- Вода **не трогалась** на этом шаге — большие пещеры могут быть залиты,
  как и раньше. Это специально отдельный шаг 2.6, не пытался чинить заранее.
- Нет способа попасть в измерение через игровой интерфейс (только команда) —
  это ожидаемо, портал будет на Этапе 6.
- gradlew/gradle-wrapper.jar по-прежнему не добавлены (см. ограничение Этапа 0);
  сборка всё ещё идёт через `gradle/actions/setup-gradle` в GitHub Actions.
